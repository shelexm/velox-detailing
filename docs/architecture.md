# Архитектура

Один репозиторий, один образ `velox-app`, четыре процесса в `compose.yaml`:

| Сервис | Что делает |
|---|---|
| `db` | PostgreSQL 17, порт наружу не публикуется |
| `migrate` | один раз при запуске: `alembic upgrade head` и идемпотентный `seed`; единственный, кто меняет схему |
| `api` | FastAPI: сайт (Jinja2), панель студии, публичное и админское API, мини-приложение Telegram |
| `bot` | aiogram 3 (long polling) и воркер уведомлений; без `TELEGRAM_BOT_TOKEN` сразу завершается |
| `backup` | `pg_dump` по расписанию с ротацией (`scripts/backup-loop.sh`) |

## Слои кода

```
app/core/       настройки, безопасность (сессии, CSRF, CSP), ошибки, логи с маскировкой, телефоны, Telegram initData
app/models/     SQLAlchemy 2: студии, пользователи, каталог, расписание, клиенты, записи, медиа, контент
app/services/   бизнес-логика: availability (чистые функции слотов), booking (единая точка создания и изменения
                записей), queries и stats (чтение для панели), media, catalog, schedule, staff, privacy, outbox
app/api/routes/ HTTP API: public, auth, admin_* , tg (мини-приложение)
app/web/        страницы сайта и панели (app/web/panel/*), шаблоны в app/templates/
app/bot/        handlers (диалог клиента и чат администраторов), keyboards, texts, worker (outbox, напоминания)
app/content/    схемы блоков сайта: из них же строятся формы в панели
migrations/     Alembic; тест сверяет модели со схемой (`alembic check`) и проверяет откат до base
```

Сайт, панель и бот вызывают одни и те же сервисы, поэтому правила записи одинаковые во всех каналах.
Подробности по записи и гонкам: `docs/booking-model.md`; безопасность: `docs/security.md`;
панель: `docs/admin-panel.md`; бот: `docs/telegram-bot.md`; фото и лицензии: `docs/media-sources.md`.

## Мультиарендность

Каждая таблица студии содержит `studio_id`, связи записей идут составными внешними ключами `(studio_id, id)`:
мастера, бокса или услуги другой студии к записи не прикрепить даже прямым SQL. Доступ к панели и API
проверяет членство пользователя в студии; чужая студия отвечает 404.

## Уведомления

Сервис записи кладёт событие в `notification_outbox` в той же транзакции, что и изменение записи. Воркер
в процессе `bot` забирает строки через `FOR UPDATE SKIP LOCKED`, отправляет через Telegram и повторяет с
растущей паузой. Сбой Telegram не влияет на запись.

## Конфигурация

Всё из `.env` (образец `.env.example`). Переход с временного адреса туннеля на домен: поменять
`PUBLIC_BASE_URL` и `ALLOWED_HOSTS`, перезапустить `api` и `bot`, без пересборки.
